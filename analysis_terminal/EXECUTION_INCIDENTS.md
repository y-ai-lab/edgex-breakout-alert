# 緊急決済・照合エラーの記録

v19.0.57は、停止後の正常な口座取得で一時的なlast_errorが消えても、
最後の照合失敗の分類・観測時刻をSQLiteの既存JSON台帳に保持する。
新規開始や停止解除は行わない。事故記録は過去の記録として表示する。

緊急決済を要求する各分岐は、最初の理由と要求の記録時刻をネットワーク送信前に保存する。
再試行・再起動で最初の理由を上書きせず、同じ決済注文を再送しない。
SL/TPの内容・有効一覧・応答・照合エラー・約定条件逸脱・一部決済残量を区別する。
所有権確認、reduce-only、リスク予算、SL/TP、緊急決済の発動条件は変更しない。

公開の稼働表示は固定の説明だけを返す。銘柄・注文ID・口座・数量・価格・損益・
SDK応答や任意の例外文字列は事故表示へコピーしない。
APIタブの既存状態履歴に説明を加え、画面タブ・エントリー条件・通知を変更しない。

旧決済の原因は補完しない。旧CLOSED記録に理由がなければ「原因未確定」と表示する。
その場合の時刻は既存の決着記録時刻であり、要求・送信・取引所約定時刻と扱わない。
要求の保存も送信・約定の証拠ではない。送信試行のない要求を決済済みと表示しない。
公開の台帳表示から特定の取引や口座の建玉ゼロを推測しない。
