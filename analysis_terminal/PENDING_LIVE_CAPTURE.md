# 押し目指値案の実時間Shadow捕捉

既存の日次API再取得研究とは別に、その時点で観測した候補をSQLiteへ固定する。[事前登録](https://github.com/y-ai-lab/edgex-breakout-alert/commit/42c46292c3406e61edfe1bba9bb3deb16095cd6a)。`pending_entry_protocol.json` と評価器のSHAを固定し、本番READY・確認条件・4H構造SL/TP・min_rrを変更しない。

捕捉後の仮想約定だけを検証する。元の `created_ms=signal close+1ms` と実際の `observed_ms` を別に保持する。捕捉中の足は途中まで進んでいるため使わず、その後に始まる15分足から評価する。元の4本待機期限は延長せず、実行可能な時間が短くなったことを明示する。現在案・Measured Move案の比較対照も同じ捕捉制約を適用し、実際の本番約定や過去replayと混ぜない。

各市場の連続した180本の確定4H/15M足を使用し、捕捉遅延は120秒以内。起動時・観測欠損後・収集起点前の既存setupを全モデルで消費済みとし、後からの初回確認を捏造しない。捕捉起点と連続観測の開始後に閉じた4H breakoutだけを対象にする。最初の適格確認のみ保存し、再起動や期限切れで再登録しない。

SQLiteの起動時刻を維持し、次のUTC日境界から非重複7日cohortを開始する。既存DB/履歴/Pushのテーブルを更新・削除せず、独立した `pending_live_*` テーブルへ保存する。既存スキャンの市場snapshotを使い、追加の市場リクエストや通知は発行しない。観測不足・遅延・指標不足はAPIの `meta.last_cycle` に残す。

最初の未開始足の判定には、その足が始まる前に実際に捕捉したsetup状態を使う。足の始まりと同時に閉じる新たな足の情報を、過去に知っていた状態として使用しない。価格・事前状態の欠損は `DATA_GAP` で停止。約定足のTP/SL接触、後続足のTP/SL両接触は `AMBIGUOUS`。不利なSL gap、費用、未確定資金の凍結を元の評価器どおり保持する。結果はcursorで追跡し、古い足の再計算で決着を置き換えない。

`GET /api/pending-entry-shadow` は読取専用。表示limitでcohort集計を縮めず、候補・約定・TP/SL・勝率・net Avg R/PF・MFE/MAE・最大連敗・資金制約付き成績・高費用の感度を返す。口座の資金予約時刻には実際の捕捉時刻を用いる。残るOPEN/不確定で最終ROIが不明ならnullを維持し、研究日次の累積値や別期間と足さない。

最初の観測は起動時のbaselineであり、登録成功だけで優位性を主張しない。20決着未満はINSUFFICIENT SAMPLE。実用性の候補判断には完全な別2期間・各50決着、勝率40%以上、費用込み平均R>0/PF>=1.2、高い費用でも平均R>0/PF>1、約定純増、資金制限後20決着以上で既知の最終ROI>0などの根拠が必要。それでも自動昇格せず、板・tick・queue・funding・実約定品質は別途検証する。過去の凍結研究判定基準は変更しない。

週別の `portfolios` は独立期間ごとの模擬口座として明示する。収集開始から全台帳を評価する `continuous_portfolios` は週の境界で資金をリセットせず、以前のOPEN/不確定の予約を次週にも保持する。週別の利益を足して連続口座のROIを推測しない。MFE/MAEは元の価格stop-distance基準、net Rは費用込みstop-risk基準である。

このAPIは実時間に捕捉した **OHLC模擬検証** であり、実注文ではない。ENTRY NOWや通知へ接続せず、比較・検証のUIタブを追加しない。独立台帳のエラーは既存collectorへ波及させず、型名のみ記録する。
