# 通知と稼働表示の境界 — v19.0.45

公開ページはログイン不要。公開APIから取引のarm・注文・鍵変更はできない。
取引の有効化は従来の非公開Railway設定／CLIだけで行う。

## Pushの端末所有確認

既存のブラウザは自身のPushSubscription（endpoint、p256dh、auth）を
`POST /api/push/session`へ送る。DB内の購読鍵と一致した場合だけ管理用Bearerを
返す。Bearerは購読の秘密authを鍵とする、用途を分離したHMAC-SHA256であり、
他のendpointの権限や取引権限には使えない。比較は定数時間。
GET/POST preferences、test、unsubscribe、既存custom-alertsの参照／削除に必須。

ブラウザはBearerをメモリにだけ保持する。sessionは通知を送らず、購読の
payload・設定・作成時刻・送信時刻を変更しない。再起動後も元の鍵で取得できる。
既存endpointを別の鍵で上書きできない。DB・VAPID鍵の再生成や移行は不要。
旧画面の無認証操作は拒否されるため、更新後の画面で操作する。

新規の購読登録自体は公開機能。これはアプリ全体のユーザーログインではない。
登録数32、16KiB／10秒のbody上限、1プロセス全体300/分・接続元60/分、
認証済みテスト送信3/分/購読で濫用を制限する。レート制限は再起動でリセットされ、
複数レプリカで共有しない。分散攻撃や登録枠占有を完全に防ぐ仕組みではない。
新規登録を所有者だけに限定する場合は、別途ログイン／招待の境界が必要。

## 外部通信とブラウザ

Pushの送信先はHTTPSのFCM・Mozilla Push・Apple Web Pushの正確なホストと
既知のパスだけ。ユーザー情報付きURL、任意ポート、query/fragment、IPや
類似ホストを拒否する。鍵はP-256公開点と16バイトauthを検証する。
登録時と既存レコード送信時の両方で確認し、HTTPリダイレクトは禁止、TLS検証は
常に有効。無効な旧購読を勝手に消したり、任意の新ホストを許可したりしない。
Web Pushエラーは固定文とHTTP statusだけを記録し、URL・鍵・応答本文を記録しない。

端末設定へのcross-site書き込みを拒否する。これはBearer所有確認の代わりではない。
HTMLはレスポンスごとのnonce CSPで同梱scriptのみ実行し、inlineイベントを禁止。
Service Workerは同一originのみ許可する。frame禁止、nosniff、no-referrer、
APIのno-storeも設定する。表示に使う通知文字列・エラー・同期銘柄はescapeする。

## 取引と表示の限界

実行エンジン・注文処理・4H/15M条件・RR・SL/TP・Shadowモデルは変更しない。
ENTRYは条件成立であり約定証拠ではない。画面にAPI稼働・管理件数・決着件数と
運用ルールを表示し、応答または口座接続が30秒以上古ければ稼働表示を外す。
既存のENTRY 120秒ガードは別途維持する。

元本はEdgeX取引口座のUSDC評価額で、Arcウォレット全体の残高とは同義ではない。
3%は仮定費用込みのSL損失予算であり、滑り・窓開け・Funding・障害で超過し得る。
日次停止はユーザー指定どおり無効なので、連敗の累積損失を制限しない。
手動計算は費用・Funding未計上の概算で、実発注設定を変更しない。

約定とSL/TP設置は非原子的。所有権が不明な同銘柄の建玉を推測して閉じない。
手動売買との競合時は停止・隔離し、ボット自身の保護注文を取り消す場合がある。
未保護建玉が残る可能性があるため、同銘柄を手動売買せず、異常時は取引所の
建玉・保護注文を確認する。実注文の全ライフサイクル検証、独立した侵入テスト、
損失上限や収益の保証を済ませたという意味ではない。

## 検証

端末所有・別購読への権限流用・鍵上書き・SSRF URL・TLS/redirect・容量/レート・
streamed body・旧購読保持・ログ非漏洩・nonceを自動検証する。
既存の時系列・口座・通知・4タブ・ENTRY鮮度テストを継続する。
Chromiumでモバイル／デスクトップ表示、CSPによるinlineイベント拒否、
稼働表示の期限切れとService Workerを確認する。実注文や研究通知は試験しない。
