本番ルールを変更する機能ではない。通知・DB・注文APIとは接続しない。
目標は約定数を増やし、勝率と費用込み収益性を比較すること。三つの改善を保証するものではない。

勝率・収益性の改善は確認できていない。直近の市場状況はすでに閲覧しており、
この検証期間を完全に未閲覧のholdoutと呼ばない。失敗したEMA pullbackや

資金1万USDC、1件最大1%リスク、最大3件、合計リスク3%、総建玉1倍、
JST日次損失上限3%の別々の模擬口座で比較した。数量を候補登録時の既知資金で

新案の開発期間は資金制約後7約定・6決着、既知の実現損益−60.66USDC。

資金上限前の全候補成績と、資金上限後の口座成績を混同しない。

これは保存済みShadowのTP/SL結果とは別の実行可能性実験で、過去結果を変更しない。
確認終値での仮想成績を、そのまま実際の約定やROIと解釈しない。

## 検証器

`pending_entry_protocol.json` に条件・期間・判断基準を固定し、
`pending_entry_replay.py` がチェックサム検証済み市場データから最初の候補を再生する。
旧版の分析関数は診断追加でソースhashが異なるため、既知の旧hashだけを許可し、
現行・Shadow双方の元の全初回エントリーを時刻・価格・SL・TPまで再現できることを確認する。
不明なhash、違うパラメータ、改変された足、再現不能な候補は拒否する。

```bash
python -m analysis_terminal.pending_entry_replay --source SOURCE --role development --output OUTPUT
python -m analysis_terminal.pending_entry_replay --source SOURCE --role validation --output OUTPUT
python -m analysis_terminal.pending_entry_replay --source SOURCE --role prospective --output OUTPUT
```

手数料5bps・スリッページ2bpsを片道ごとに仮定する。実際のユーザー手数料、
板・スプレッド・最小価格刻み・約定順序・fundingは検証できていない。
OHLCでの押し戻り接触は仮想約定モデルで、指値の実約定保証ではない。
signal close+1ms以前の足は除外し、形成中の足も使わない。
押し戻り約定足のTPまたはSL接触はAMBIGUOUS、後続足の両方接触もAMBIGUOUS。
欠損後のTP/SLを利益として確定しない。SLを飛び越えるギャップは追加損失として扱う。

ROIはリスク単位Rから換算せず、資金制約と費用を反映した口座損益から計算する。
曖昧・欠損の資金を解放せず、口座ROIを不明と表示する。
最大既知現金ドローダウンは未実現損失を含むequity drawdownではない。
未決済や除外件数、観測不足も併記する。

## 継続収集

`.github/workflows/strategy-research.yml` が毎日00:30 UTC（09:30 JST予定）に
読み取り専用で公開データを取得し、比較と出典をartifactへ保存する。
GitHubの実行時刻は遅れる場合がある。最初の期間は10/7 00:00 UTC開始。
最初の完了UTC日が得られる10/8以降に分析可能で、それまではWAITINGを出す。
登録開始日から固定の7日区切りで比較し、途中集計は `period_complete=false`。
過去APIからの再取得なので、パラメータを事前固定した将来期間の研究であり、
本番で捕捉したエントリー/実約定のforward成績には数えない。

条件変更・通知・本番昇格・実注文は自動化しない。サンプル不足は待つ。
十分なサンプルで期待値≤0またはPF≤1ならKILL。結果を見て同じデータへ条件を合わせない。
本番昇格には別途、実時間のShadow決着20件以上、Avg R>0、PF>1を最低条件として、
費用込み収益性、未使用期間、資金制約・損失・データ品質を確認する必要がある。
単独で20件を満たしたことを採用の保証としない。

## v19.0.24: 費用控除後の成績を並列集計（2026-10-06）

エントリー・SL・TP・min_rr・昇格条件は変更していない。`/api/strategy-comparison`、`/api/shadow-v2`、`/api/readiness-history`、`/api/btc-wave` に読み取り専用の `cost_adjusted` 集計を追加した（日次履歴は `cost_adjusted_signals`）。既存のgross集計は維持する。

[取得時点の成績](cost_review_latest.json): Shadow v2は107 setup、59 resolved、18 TP / 41 SL。TP到達率30.51%、gross Avg R -0.0847 / PF 0.8780。片道手数料5bps・スリッページ2bpsを仮定すると、net Avg R -0.1637 / PF 0.7803、黒字率30.51%。107候補すべての費用込みRRは2未満。これは既存のgross fixed 2Rを費用控除した結果であり、候補を新たに除外するルールではない。本番昇格しない。現行戦略は2 resolvedでINSUFFICIENT SAMPLE。

TP到達率と費用控除後の黒字率を分離する。verified outcome・凍結価格・記録済みRの整合性を検証し、不明/AMBIGUOUS/履歴不完全/重複setup/未識別legacyを除外する。画面上の表示件数制限は集計対象を減らさない。読み取りによるDB更新は行わない。

新集計のRは元のentry-to-stop価格差を基準とする。前節のpending-entry研究は費用込みstop-risk基準なので、数値を同じRとして直接合算しない。実約定、funding、板・spread・queue、記録済みexit価格を超えるgap損失はモデル化していない。これは仮定に基づく診断で、実運用のROIではない。資本配分がないためportfolio_roi_pctはnullとする。

固定済みpending-entry仮説の収集期間・パラメータは維持。最初の完了日データは2026-10-08 UTC以降であり、待機期間に同じ過去期間を再調整しない。
